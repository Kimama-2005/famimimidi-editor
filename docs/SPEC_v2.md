## 1. 目的と範囲

ファミコン用 MIDI 音源カートリッジ「ふぁみみみっでぃ」(作者 へけけくんさん、非公式ソフト)の、Windows 用の音色エディタ・ライブラリアン・演奏補助ソフト。

| できること | 中身 |
|---|---|
| 音色を作る | ch ごとの音色(CC の値+ch5 は波形)を、かんたん表示/詳細表示で編集して送る |
| しまう | 音色と演奏セットをパソコンのライブラリに保存・読み込み・バックアップ |
| 弾く | 外部の鍵盤(microKEY2・KROSS2)の演奏を、割り当て表で 5ch に振り分ける。コードモード(1本指でコード) |
| カートリッジに入れる | 音色を保存場所(40か所)に書き込む、呼び出し番号・電源を入れたときの音色・波形の登録。「整える」 |
| 書き出す | MIDI ファイル(Domino・Cubase 用) |

範囲外: カートリッジの改造、ファミコンのコントローラーの操作(切り替えは MIDI 側で行う)、オンライン機能。

動く環境: Windows 11、Python 3.14(3.13 も可)、pywebview(WebView2)。**オフラインで動く**(部品は `vendor/wheels`)。

## 1.5 設計の考え方(場所が振る舞いを決める)

今の版は「困ったら設定を1つ足す」をくり返して、設定項目が散らばった。作り直しでは次を守る。

1. **アプリは「ふぁみみみっでぃ全体という1つの楽器」を扱う**。その楽器の今の状態が「作業中の演奏」(= 1つの演奏セット)で、画面はそれを見て・触るためのもの
2. **画面は2つの場所に分ける**
   - **演奏する場所**(「♪ 演奏セット」タブ): 演奏セットとして5chをどう鳴らすか。鍵盤の割り当て、コードモード、曲、ペダル・レバー
   - **音色をつくる場所**(「1」〜「5」のタブ): 1つの ch の音色を作る
3. **振る舞いは、いる場所で決まる**。切り替えのスイッチを作らない
   - 「♪ 演奏セット」タブにいる間、鍵盤は演奏セットどおりに鳴る(割り当て表、またはコードモード)
   - 「1」〜「5」のタブにいる間、鍵盤はその ch だけを鳴らす(音色を作るときに、その音だけを聴く。**最初の版の「選んでいる ch を鳴らす」はこの形で残す**)
4. **設定は、その設定が関わるものの隣に置く**。まとめて「設定」画面に並べない(接続とテーマだけは別)
5. **決められるものは自動にする**。ユーザーが選ぶのは、音楽として意味のある違い(どの配置で弾くか、どんな奏法か)だけ。細かい数値は「奏法プリセット」にまとめる
6. **見て分かるようにする**。割り当ては鍵盤の絵の上の色の帯、配置は鍵盤の図、音色はグラフ。ch はどこでも同じ色(1 赤・2 橙・3 青・4 灰・5 緑)
6.5 **言葉は音楽ソフトで普通に使うもの**(ボイシング、ポリ、ユニゾン、ADSR、デチューン、ストラム など)。やさしく言い換えすぎない。説明は「?」に入れる
7. **鍵盤(外部の MIDI キーボード)は音を鳴らすことにだけ使う**。曲やキーの切り替え・機能キーには使わない(画面とパソコンのキーで操作)

## 2. 用語

画面と説明では左の言葉を使う(ユーザーから「PC」「マクロ」は分かりにくいと言われた)。中の言葉はコードの中だけ(詳細な管理の画面は作らない)。音楽の言葉は音楽ソフトで普通に使うもの(1.5-6.5)。

| 画面の言葉 | 中の言葉 | 意味 |
|---|---|---|
| 音色 | Tone | 1つの ch で鳴らす音の設定(CC の値の組+ch5 は波形) |
| 演奏セット | Performance | 5ch 分の音色+ch1・ch2 の紐付け+鍵盤の割り当て表+ペダル・レバー+コードモードの設定。読み込むと全部が切り替わる |
| 紐付け(🔗) | link12 | ch2 も ch1 の音色で鳴らす。外すと保管していた ch2 の音色が戻る |
| ペダル・レバー | controls | サスティンペダル・ピッチベンド・モジュレーションの送り先と働き |
| ボイシング / ボイス1〜3 | voicing / voices | コードモードで構成音を ch1・ch2・ch5 に割り振ること |
| 奏法プリセット | style | コードの鳴らし方のひな形(ピアノ・オルガン・ギター・パッド) |
| 作業中の演奏 | Session | いま画面で触っている演奏セット(保存前のもの)。アプリを閉じても残る |
| 保存場所 1〜40 | macro 1〜40 | カートリッジのユーザーマクロ |
| 呼び出し番号 89〜128 | PC89〜128 | 保存場所を呼び出すプログラムチェンジ(送信値は 88〜127) |
| 電源を入れたときの音色 | startup macro(CC#50) | ch ごとに、電源 ON で自動で実行されるマクロ |
| 波形の登録 61〜76 | wave PC61〜76 | ch5 の波形メモリの波形をカートリッジに保存する先 |
| 割り当て表 | KeyboardMap | 外部の鍵盤のどの鍵をどの ch で鳴らすか |
| コードモード | ChordMode | 1つの鍵でコードを鳴らす演奏のしかた |
| 曲(コードセット) | ChordBook / Song | コードモードの12曲分のコード進行 |
| 土台 | base | 「整える」で作る、ch ごとの共通の設定(電源ONマクロに入れる) |

## 3. 機器の事実(必ず守る)

`docs/03_verified_findings.md` の確定事項(F番号)のうち、設計に効くもの。**未確認の事柄を確定として扱わない**(11章)。

### 3.1 チャンネル
| ch | 音源 | 強さ | 鳴る範囲 | 補足 |
|---|---|---|---|---|
| 1 | パルス1 | 16段階 | 33〜108 | デューティ 12.5/25/50/75%(CC#70) |
| 2 | パルス2 | 16段階 | 33〜108 | |
| 3 | 三角波 | 鳴る/鳴らない | 21〜96 | 音量(CC#7)は効く(F40) |
| 4 | ノイズ | 16段階 | 0〜127 | ノート番号で音の高さ(CC#17 で並び順) |
| 5 | DPCM / 波形メモリ | DPCM: 鳴る/鳴らない、波形: 32段階 | 0〜127 | CC#18 で切り替え(0〜63 DPCM、64〜127 波形メモリ)。**DPCM は音量が効かない(F25)、波形メモリは効く(F41)** |

- 各 ch は**単音**(Mode4 固定)。同時に鳴らすには ch を分けるしかない
- 電源 ON のときのボタンで ch1〜5 / 6〜10 / 11〜15 にずれる(`ch_offset` 0/5/10)
- 三角波とパルスを同時に鳴らすと歪むのは、ユーザーのファミコン用アンプのせい(U16 解決)。音質の判定では差し引く

### 3.2 カートリッジ(書き込みは取り消せない)
1. **ユーザーマクロに記録できるのは先頭10個の CC まで**。11個目以降は黙って捨てられる → 重要度順(5.3.4)に並べる
2. **CC#51 の値 v = プログラムチェンジのデータバイト v**(0始まり)。v=92 → PC93。画面では両方を書く
3. **CC#121 は鳴っている音を全部止める** → 音色の切り替えに使わない
4. 記録中(CC#45=1〜40 〜 CC#45=0)に送った CC は、記録されると同時に音にも効く
5. **カートリッジの中身は読み出せない** → 何を書いたかはアプリの控え(5.6)だけが頼り
6. マクロ・PC 割り当て・CC#50・波形の登録は電源を切っても残る(F14)
7. **マクロは ch を記録しない**。実行した ch に効く(F20)。PC→マクロの表は全 ch 共通、マクロは PC を受けた ch だけに効く(F24)
8. CC#50 は効く(F19)。値は「電源 ON で今のマクロを実行する ch」
9. 音量0(CC#7=0)は PC を変えても戻らない(F18)
10. 記録中は、その時点と同じ値の CC も記録される(F21)
11. 「復旧用ファイルを再生した」という報告だけで状態を確定させない(F26)。書き込んだ後は「1つずつ試す」で確かめる

### 3.3 送信
- MIDI は 1バイト 約0.32ms。CC 1個 ≒ 0.96ms。32個送ると約30ms 遅れる
- 波形データの SysEx(`F0 00 70 7F d0..d15 F7`)は、その場で ch5 の波形メモリに効く(F32)。カートリッジには保存されない
- 波形の登録(`F0 00 71 7F NN F7`、NN=60〜75 → PC61〜76)は保存される(F33)
- デチューン(CC#85)は、ファミコンの音程の段階に丸められる(F36)。+8 セントは音によって 0 になる
- 新しい音のノートオン → 古い音のノートオフ の順で持ち替えると、音が途切れない(F39)。エンベロープがかかり直すかは未確認(11章)

### 3.4 パソコン側
- Windows 11 は同じ MIDI 入力を**複数のソフトで同時に開ける**。アプリを2つ動かすと演奏が二重に届く → アプリは1つだけ(`single`)。Domino・Cubase などが鍵盤を直接流していることもある(起動時に警告)
- 古いドライバは1ポートを1ソフトしか開けないことがある → つながらないときは「Domino/Cubase を閉じて」と案内
- Domino は1トラックに複数 ch が混ざった MIDI ファイルを読めない → 書き出しは format 1、ch ごとに1トラック、文字は cp932

## 4. 全体の構成

### 4.1 層(上の層は下の層だけを使う)

```
画面(web: HTML/CSS/JS)       … 表示と操作だけ。値の計算をしない
  │ Bridge(pywebview の js_api)… 画面⇔中身の窓口。JSON にできるものだけを受け渡す
アプリ(app)                   … 状態の持ち主。作業中の演奏・ライブラリ・控え・設定を持ち、操作を受けて下に指示する
  ├ 演奏(performance)         … 外部鍵盤の振り分け(KeyboardMap)、コードモード(ChordMode)。時間で動くもの
  ├ カートリッジ(cartridge)   … 書き込みの計画・実行・控え
  ├ 音楽の計算(music)         … コード名の解析、ボイシング、鍵盤の配置(画面からも機器からも独立)
  └ データ(model)             … 5章のデータ型と JSON の読み書き(純粋。送信しない)
機器(device)                   … MIDI ポート(winmm)、送信の関所、送信ログ
```

**約束**
- 送信は必ず**関所**(6.1)を通す。ほかの道から送らない
- データ型(5章)は「どのファイルに保存されるか」「誰が書き換えてよいか」を1つに決める。同じ情報を2か所に持たない
- 時間で動くもの(ずらし・猶予・書き込み)は1本のスケジューラで動かす。画面への知らせ(evaluate_js)は1本のスレッドから(複数のスレッドや画面のスレッドから呼ぶと固まった)

## 5. データ構造(厳密な定義と置き場所)

### 5.0 一覧: 何を、どこに、誰が書くか

| データ | ファイル | 書き換えてよい部品 | 保存のきっかけ |
|---|---|---|---|
| 音色(Tone)の一覧 | `user_data/library.json` の `tones` | アプリ(ライブラリ操作) | ライブラリの「保存」「上書き」「名前」「削除」「取り込み」 |
| 演奏セット(Performance)の一覧 | `user_data/library.json` の `performances` | アプリ(ライブラリ操作) | 同上 |
| **作業中の演奏(Session)** | `user_data/session.json` | アプリ(画面の操作すべて) | 変わるたび(少し間引いて自動保存) |
| 曲(ChordBook) | `user_data/chordbook.json` | アプリ(曲の編集・取り込み) | 「保存」・取り込み |
| カートリッジの控え(CartMirror) | `user_data/cartridge.json` | カートリッジの書き込み部品**だけ** | 書き込みの成功・失敗のたび |
| アプリの設定(Prefs) | `user_data/prefs.json` | アプリ(接続と設定) | 変わるたび |
| 送信ログ | `logs/YYYY-MM-DD.log` | 関所だけ | 1行ずつ |

- **音楽の中身(音色・割り当て・コードの設定)は Prefs に入れない**。Prefs は「どのポートにつなぐか」「テーマ」など、演奏と関係ないものだけ
- 保存は「一時ファイルに書いて置き換える」(途中で落ちても壊れない)
- どのファイルも先頭に `"format": "<名前>-v<番号>"` を持ち、読むときに番号を見て直す(移行)

### 5.1 共通の小さな型

```text
Ch        = 1〜5 の整数(画面の ch。送るときに ch_offset を足す)
CC        = 0〜127 の整数(CC 番号)
Value     = 0〜127 の整数
Note      = 0〜127 の整数(60 = C4。画面の鍵盤と同じ)
Wave16    = 長さ16の配列、各 0〜15(ch5 の波形メモリ)
Kind      = "pulse" | "triangle" | "noise" | "dpcm_wave"   … ch の種類(ch1・2=pulse、3=triangle、4=noise、5=dpcm_wave)
Id        = 英数字と _ の文字列(名前から作り、重ならないように6桁の乱数を足す)
Time      = ISO 8601 の日時文字列(タイムゾーン付き)
```

### 5.2 音色(Tone)

1つの ch で鳴らす音の設定。**どの種類の ch 用か**を持つ(パルス用の音色は ch1・ch2 のどちらにも入れられる)。

```json
{
  "id": "piano_lead_3f2a1c",
  "name": "ピアノ風リード",
  "kind": "pulse",
  "params": [[70, 48], [79, 0], [75, 56], [72, 30]],
  "wave": null,
  "category": "lead",
  "notes": "弾いた瞬間が一番大きく、だんだん消える",
  "source": "",
  "created": "2026-11-05T12:00:00+09:00",
  "updated": "2026-11-05T12:00:00+09:00"
}
```

| 項目 | 型 | 決まり |
|---|---|---|
| `params` | `[[CC, Value], ...]` | **既定値と違う CC だけ**。並び順に意味がある(カートリッジに入れるときの優先の手がかり)。同じ CC は1回だけ。書き込み系・リセット系の CC(45〜51、120、121、123)は入れない。**演奏セットが持つ CC(#82 ベンド幅・#20 CC#1⇔#70 入替、5.3.5)と、演奏中に動かす値(#2 ブレスの値・#64 ホールド1・#84 ポルタメント・コントロール)も入れない** |
| `wave` | `Wave16` か `null` | `kind = "dpcm_wave"` のときだけ持てる。`null` なら「波形は今のまま」 |
| `kind` | Kind | ch の種類。ch に入れるときに合っているか確かめる(パルス用をノイズに入れない) |
| `category` | `"lead"`/`"backing"`/`"bass"`/`"drums"`/`"fx"`/`"other"` | |

**ch に入れる(6.2)とは**: その ch の全項目を既定値にしてから `params` で上書きし、全部送る。`wave` があれば波形も送る。CC#121 は使わない。

今の版との違い: 今は `channel`(1〜5)を持つ。作り直しでは `kind` にする(ch1 用・ch2 用の区別をなくす)。`cc` → `params`、`wave` は後付けだったものを最初から持つ。

### 5.3 演奏セット(Performance)と作業中の演奏(Session)

#### 5.3.1 演奏セット
**ふぁみみみっでぃ全体を1つの楽器として**どう鳴らすかをまとめたもの。読み込むと全部が切り替わる。

```json
{
  "id": "piano_accompaniment",
  "name": "ピアノ伴奏(コードモード)",
  "notes": "",
  "slots": {
    "1": {"tone": { …音色の中身(id 以外)… }, "from": "piano_lead_3f2a1c"},
    "2": {"tone": { … }, "from": ""},
    "3": {"tone": { … }, "from": ""},
    "4": {"tone": { … }, "from": ""},
    "5": {"tone": { …kind=dpcm_wave、wave あり… }, "from": ""}
  },
  "link12": true,
  "keyboard": { …割り当て表(5.4)… },
  "controls": { …ペダル・レバー(5.3.5)… },
  "chord": { …コードモードの設定(5.5)… },
  "created": "…", "updated": "…"
}
```

| 項目 | 決まり |
|---|---|
| `slots` | **ch1〜ch5 の5つを必ず持つ**。中の音色は**コピー**(ライブラリの元の音色を直しても変わらない)。`from` は元の音色の id(画面で「元: ○○」と出すためだけ。無ければ空) |
| `slots.N.tone.kind` | ch N の種類と一致すること |
| `keyboard` | 割り当て表。コードモードが OFF のときの外部鍵盤の振り分け |
| `chord` | コードモードの設定と **ON/OFF**。演奏セットの中で、ch1〜ch5 と同じ階層にある「演奏のしかた」 |
| `link12` | ch1 と ch2 の紐付け(5.3.3)。紐付け中は `slots.2.kept` に ch2 の音色を保管する |
| `master` | マスターボリューム `{"map": 0〜127, "chord": 0〜127}`(2026-11-17 ユーザー要望)。5ch の音量 CC#7 に「× 値 / 127」で掛けて送る(音色の値は変えない。カートリッジへは書かない)。割り当て表で弾くとき(`map`、初期値 127)とコードで弾くとき(`chord`、初期値 64。4つの ch が重なって大きいため)で別々。いまの弾き方のほうが効き、弾き方が変わると音量を送り直す。0 のときはノートオンを送らない。画面は ♪ のタブの「弾き方」の行のつまみ(いまの弾き方のほうを動かす)。※一度入れた「コードモードの間だけ上3声とベースを半分に」は、これに置き換えてなくした |
| `controls` | サスティンペダル・ピッチベンド・モジュレーションをどの ch へ、どう効かせるか(5.3.5) |

#### 5.3.2 作業中の演奏(Session)
**いま画面で触っているもの = 1つの演奏セット**として持つ。今の版では「今の 5ch の音色」がどこにも保存されず、割り当て表とコードの設定が Prefs に入っていた。それを1か所にまとめる。

```json
{
  "format": "famimimidi-session-v1",
  "performance": { …演奏セットと同じ形(id は読み込んだセットの id か ""、name も)… },
  "loaded_from": "piano_accompaniment",
  "dirty": true
}
```

| 項目 | 決まり |
|---|---|
| `performance` | 画面の値そのもの。**音色を1つ変えたら、ここの `slots.N.tone.params` が変わる**。送った値の控えも兼ねる(カートリッジは読めないので、アプリが最後に送った値がここ) |
| `loaded_from` / `dirty` | どの演奏セットから来たか、保存してから変えたか(演奏セットの名前の横に「変更あり」の印) |

- **鍵盤の受け方は保存しない**(1.5-3: いる場所で決まる)。今の版の「開いているタブの ch / 割り当て表 / 鍵盤の ch のまま」の切り替えと、「スルー ON/OFF」はなくす
- **接続したら(起動時も)、作業中の演奏を全部送る**(10章-2)。ファミコンの電源を入れ直すと、ふぁみみみっでぃ側は電源を入れたときの状態に戻っていて、アプリの覚えている音色とずれるため。5ch 分で 0.2秒ほど。手で送り直したいときのために、演奏セットの名前の横に「送り直す」を置く
- ライブラリで演奏セットを**読み込む** = ライブラリのセットを Session にコピーして全部送る
- ライブラリに**演奏セットとして保存** = Session をライブラリにコピー
- 「1」〜「5」のタブの左の一覧で**音色を選んで「この ch に入れる」** = その音色を Session の `slots.N` にコピーして送る(`from` を入れる)
- 同じ一覧の**「新しく保存」「上書き保存」** = Session の `slots.N.tone` をライブラリの音色としてコピー

#### 5.3.3 ch1 と ch2 の紐付け(`link12`)
パルスの ch1 と ch2 は、同じ音色にしたいときと、別々にしたいときがある(ユーザーの要望)。

```json
"link12": true,
"slots": { "1": {"tone": {…やわらかピアノ…}}, "2": {"tone": {…やわらかピアノ…}, "kept": {"tone": {…ファミコンリード…}, "from": "…"}} }
```

- **紐付けると**: ch2 の今の音色を `slots.2.kept` に**保管**し、ch2 も ch1 の音色で鳴らす(`slots.2.tone` = ch1 のコピー)
- **紐付け中**: ch1・ch2 のどちらのタブで音色を変えても、両方に同じ変更が入る(音色を選んだときも両方)。ch2 のタブには「ch1 の音色を使用中。ch2 の音色『○○』は保管中」と出す
- **外すと**: ch2 は `kept` の音色に戻る(`kept` は消す)。紐付け中に変えた分は ch1 にだけ残る。`kept` が無ければ(最初から紐付いていた演奏セットなど)ch2 は ch1 の音色のまま
- `kept` は演奏セットと一緒に保存される(閉じても消えない)
- 置き場所: 「1」と「2」のタブの間の 🔗(概念上「ch1 と ch2 の関係」なので、その2つのタブの間に置く)。押すと切り替わる
- 割り当て表で ch1・ch2 を「ポリ(2音)」にしたときは、同じ音色でないと和音がそろわないので、自動で紐付ける(同じく保管する)
- コードモードでは ch1 と ch2 は別のボイス。`link12` は音色の話なので、コードモードでも効く

#### 5.3.4 カートリッジに入れるときの10個の選び方(重要度)
`params` から既定値と同じものを除き、次の順で先頭10個:
`70, 23, 24, 79, 75, 72, 1, 78, 73, 65, 12, 92, 25, 26, 27, 76, 77, 86, 87, 5, 81, 85, 88, 89, 80, 84, 83, 21, 22, 9, 13, 14, 15, 16, 30, 3, 2`(表に無いものは後ろ)。「整える」(6.6.4)のときは別の計算。

#### 5.3.5 ペダル・レバー(`controls`)
外部鍵盤のサスティンペダル・ピッチベンドレバー・モジュレーションレバーを、この演奏セットでどう効かせるか。

```json
"controls": {
  "pedal": {"to": [1, 2, 3, 5], "use": "hold"},
  "bend":  {"to": [1, 2], "range": 2},
  "mod":   {"to": [1, 2], "use": "vibrato"}
}
```

| 項目 | 選べるもの | 送るもの |
|---|---|---|
| `pedal.to` / `bend.to` / `mod.to` | 送る ch(1〜5 の組) | 外部鍵盤から来た値を、ここに書いた ch へ |
| `pedal.use` | `"hold"` ホールド / `"off"` 使わない | CC#64(ホールド1)。離した後の伸びは各音色のホールド・タイム(CC#83)。コードで弾いているときは、踏んでいる間コードを保持する |
| `bend.range` | 2 / 7 / 12(半音) | 演奏セットを読み込んだとき CC#82(ピッチベンド・センシティビティ)を `bend.to` の ch へ。**CC#82 は ch1〜3 だけ**(ch4 は既定の幅) |
| `mod.use` | `"vibrato"` ビブラート / `"duty"` デューティ比 / `"expression"` エクスプレッション | レバーの値を、ビブラート = CC#1、デューティ比 = CC#70、エクスプレッション = CC#11 に**アプリが置き換えて**送る(カートリッジの CC#20 入替は使わない)。デューティ比は ch1・ch2 だけ |

- **既定値**: ひな形・割り当て表を変えたとき、`bend.to`・`mod.to` は**鍵域が一番高い ch(メロディ)と、それにポリ・ユニゾンでつながる ch**、`pedal.to` は使っている ch すべてに自動で付け直す。そのあと手で変えてよい
- コードモードでは、`to` に入っているボイスへ送る(ベース = ch3、ボイス1・2・3 = ch1・ch2・ch5)
- ビブラートの深さ・速さ(CC#81 無効区間など)は音の性格なので音色に残す
- 画面: 「♪ 演奏セット」タブの「ペダル・レバー」カード。1行に1つ、ch の番号ボタン(ch の色)と働きの選択

### 5.4 割り当て表(KeyboardMap)

```json
{
  "pair": "poly",
  "parts": {
    "1": {"on": true,  "lo": 60, "hi": 127, "shift": 0},
    "2": {"on": false, "lo": 0,  "hi": 127, "shift": 0},
    "3": {"on": true,  "lo": 0,  "hi": 59,  "shift": -12},
    "4": {"on": false, "lo": 0,  "hi": 127, "shift": 0},
    "5": {"on": false, "lo": 0,  "hi": 127, "shift": 0}
  }
}
```

| 項目 | 決まり |
|---|---|
| `parts.N.lo` / `hi` | 鍵域(lo ≦ hi、0〜127)。**1つの鍵は、鍵域に入るすべての ch で鳴る**(重ねれば同時、ずらせば分かれる) |
| `parts.N.shift` | -24/-12/0/12/24(オクターブ単位) |
| `pair` | ch1 と ch2 の組み方: `"off"` ch1 のみ / `"poly"` ポリ(2音。ch1 の鍵域を ch1・ch2 に1音ずつ。3音目は一番古い音を止める) / `"layer"` ユニゾン(重ねる。ch1 の鍵域を両方へ)。`"off"` 以外のとき ch2 の行は使わない |

ピッチベンド・モジュレーション・ペダルの送り先は演奏セットの `controls`(5.3.5)。割り当て表を変えると既定値を付け直す(今の版の「ホイール」の列はなくす)。

ひな形(画面で選ぶとこの表になる): ch1 だけ / ポリ(2音)/ ユニゾン / ベース+メロディ / ベース+ポリ / ベース+ユニゾン(ベースは ch3、境目 C4)。**割り当て表はカートリッジに保存できない**(アプリが振り分ける)。

### 5.5 コードモードの設定(ChordSettings)

ユーザーが選ぶのは、音楽として意味のある違い(配置・ボイシング・奏法)だけ。今の版の細かい数値(15項目)は「奏法プリセット」と自動の決まりにまとめる。

```json
{
  "active": true,
  "layout": "song",
  "method": "split",
  "style": "piano",
  "spread": 30,
  "bass": "low",
  "glide": false
}
```

| 項目 | 選べるもの | 画面 |
|---|---|---|
| `active` | 演奏セットで「コードで弾く」か「割り当て表で弾く」か | 「♪ 演奏セット」タブの「弾き方」(割り当て表で弾く / コードで弾く)。パソコンのスペースキーでも切り替え |
| `layout` | `"song"` 曲の弾きやすさ重視 / `"degree_r"`・`"degree_l"` 度数+補足(右手・左手で基本コード)(6.5.2) | 鍵盤の図の上で選ぶ(図がその場で変わる) |
| `method` | `"split"` 4声 / `"arp"` アルペジエーター(ch1 で和音をアルペジオ、ch3 はベース) | 「ボイシング」カード(ベース・ボイス1・ボイス2・ボイス3 の4枠)の上で選ぶ |
| `style` | 奏法プリセット: `"piano"` ピアノ(下からストラム・毎回打鍵)/ `"organ"` オルガン(同時発音・レガート)/ `"strum"` ギター(上から速いストラム)/ `"pad"` パッド(スロー アタック/リリース) | 絵の付いたボタンで選ぶ |
| `spread` | ストラム幅(0〜500ms)。プリセットから好みで変えられるのはこの1つだけ | プリセットの下のつまみ(ms を表示) |
| `bass` | ベースの音域 `"low"`(C2〜)/ `"mid"`(C3〜) | ボイシングのベースの枠 |
| `glide` | グライド | ボイシングのボイス1の枠 |

**プリセットごとの中の値**(画面には出さない):

| style | strum_order | strum_change | release_ms | jitter_ms | retrigger |
|---|---|---|---|---|---|
| piano | 下から | ON | 40 | 6 | ON |
| organ | 下から | OFF | 0 | 0 | OFF |
| strum | 上から | ON | 60 | 4 | ON |
| pad | 下から | ON | 300 | 10 | ON |

**自動で決めるもの**(今の版では設定だった):
- つなぎの猶予 = 80ms 固定
- 3オクターブに収める = いつも
- アルペジエーターの ch = ch1
- ボイス1〜3 の音域 = C4〜C6(ベースが `"mid"` なら1オクターブ上げる)
- `glide` のときは「打ち直さない」(すべらせるため)

### 5.6 曲(ChordBook)

**全演奏セット共通**で1冊。OtamaChord Studio のコードセット(`otamachord-set-v1`)と同じ形で読み書きできる。

```json
{
  "format": "otamachord-set-v1",
  "name": "ライブセット",
  "songs": [
    {"name": "気まぐれロマンティック", "key": 2, "text": "GM7 A | F#m7 Bm7 | …"},
    … 12曲 …
  ],
  "common_row": null,
  "bass_floor": null
}
```

| 項目 | 決まり |
|---|---|
| `songs` | 必ず12曲(空きは name/text が空)。`key` は 0〜11 か `null`(自動推定) |
| `text` | コード名を空白・`|`・改行で区切る。読めないコード名は画面で知らせる |
| `common_row` | オタマ本体用(オタマのコードセットと同じ形にするため残す)。このアプリは使わず、読み込んだ値をそのまま書き出す |
| `bass_floor` | オタマ本体用。このアプリは使わず、書き出すときも `null`(オタマ側の値を上書きしない) |

取り込み: OtamaChord Studio のコードセット / `songs.json`(曲の配列)/ **保存した ChordWiki のページ(HTML)**(コードと小節線だけ。歌詞は取り込まない。曲名の「(…主題歌)」は外す)。取り込んだページの場所は曲の `source` に覚える(2026-11-05 ユーザー要望: 歌詞を**表示だけ**する。6.5 の進行の欄)。

### 5.7 カートリッジの控え(CartMirror)

**カートリッジの中身は読めないので、アプリが書いたことの記録**。書き換えてよいのはカートリッジの書き込み部品だけ。

```json
{
  "format": "famimimidi-cart-v1",
  "macros": {
    "11": {"params": [[70, 48], …], "label": "J-POP 標準", "certain": true,
           "from": "jpop_v1_standard", "role": "tone", "written": "…"}
  },
  "pc_map": {"89": 19, "90": 19, "93": 11, …},
  "startup": {"1": 4, "2": 19, "3": null, "4": null, "5": null},
  "waves": {"61": {"name": "三角", "samples": [0, 2, …], "written": "…"}},
  "history": [{"time": "…", "action": "record", "macro": 11, "pc": 93, "ok": true, "note": ""}]
}
```

| 項目 | 決まり |
|---|---|
| `macros` | マクロ番号(1〜40)→ 中身。`params` は**実際に記録した10個以内の CC**(音色の params ではない)。`certain=false` は「書いたはずだが失敗した・途中で止まった」= 中身不明。`role` は `"tone"`(音色)/ `"base"`(整えるの土台、ch 付き `"base:1"`)/ `"neutral"` |
| `pc_map` | 呼び出し番号(89〜128)→ マクロ番号。`null` は不明 |
| `startup` | ch → 電源ONマクロ番号(`null` は不明) |
| `waves` | 波形の登録先(61〜76)→ 波形。`samples=null` は登録途中で失敗 |
| `history` | すべての書き込みの記録(いつ・何を・成功したか) |

決まり: マクロ 19 は「音量最大(空きの呼び出し番号の割り当て先)」、20 はテスト用の無音(予約)。今のユーザーのカートリッジの状態は `docs/03` の「カートリッジの現在の状態」と、今の `user_data/cartridge.json` が正。

## 6. 振る舞い

### 6.1 送信の関所(device/gate)
すべての送信はここを通る。順に判定:
1. **書き込み中**なら、書き込みジョブ以外は送らない(記録中に届いた CC はマクロに入ってしまう)
2. **書き込み系の CC(#45・#50・#51)と波形の登録 SysEx** は、確認画面を通った書き込みジョブ(`write_ok`)以外は送らない。波形データの SysEx(試聴)は送ってよい。それ以外の SysEx は送らない
3. **音量(CC#7)かエクスプレッション(CC#11)が0の ch へのノートオンは送らない**(ふぁみみみっでぃは音量0でも強く弾くと鳴ることがあった。法則は未確認 = V0)。値は Session で判断
4. 送ったら、時刻・バイト列・日本語の説明・出どころ(エディタ/スルー/コード/画面鍵盤/試聴/書き込み/パニック)をログに書く。送らなかったものも理由付きで書く
- スライダーの CC は間引く: 同じ (ch, CC) は 20ms ごとに最新の値だけ
- パニック: 全 ch に CC#123 → CC#120(CC#121 は使わない)。コードモードの音も止める
- 入力のクロック(F8)・アクティブセンシング(FE)は捨てる

### 6.2 音色を ch に入れる
1. ch の全項目を既定値にする+音色の `params` で上書き → Session に入れる → 間引きの列に入れる(全部送る)
2. `wave` があれば波形データの SysEx を送る
3. `link12` のとき ch1・ch2 の両方に入れる(5.3.3)
4. コードモードが ON の間に変えている設定(6.5.6)は、Session には入れるが送らない

### 6.3 演奏セットを読み込む
順序を守る(順番が逆になって、遅れて届いた値に上書きされた不具合があった):
1. 外部鍵盤で鳴っている音を止める
2. Session を置き換える
3. ch1〜ch5 に音色を入れる(6.2)
4. ペダル・レバーの設定を入れる(`bend.range` の CC#82 を送る、5.3.5)
5. コードモードの設定を入れ、`active` に合わせて ON/OFF(ON なら 6.5.6 の上書きを、**音色と同じ間引きの列**に入れる = 最後の値が勝つ)

**確認はしない**(2026-11-17 ユーザー要望: 切り替えの確認がじれったい)。左の一覧で名前を押したらすぐ読み込む(「読み込む」ボタンは無い。いま読み込んでいて変更の無いセットを押しても読み直さない。続けて押しても1回だけ)。読み込む前の作業中の演奏(保存していない変更も)を1つ覚えておき、読み込んだ知らせの「元に戻す」で戻せる(1回だけ。戻したときも同じ順序で送り直す)。

### 6.4 外部鍵盤の振り分け(router)
**いる場所で決まる**(1.5-3):

| いる場所 | 外部鍵盤・画面の鍵盤 |
|---|---|
| 「1」〜「5」のタブ | その ch だけで鳴らす(音色づくり)。`link12` でも鳴らすのは開いている ch だけ。**外部の鍵盤は切り替えられる**(下) |
| 「♪ 演奏セット」タブ・コードモード OFF | 割り当て表(5.4)どおり |
| 「♪ 演奏セット」タブ・コードモード ON | コードモード(6.5) |
| ライブラリ・カートリッジなど重ねて開く画面 | 下にある場所に従う |

- **1〜5 のタブでの外部の鍵盤**(2026-11-05 ユーザー要望で追加): 下の鍵盤の欄の [この ch だけ] [演奏セットどおり]。「演奏セットどおり」(`prefs.kb_follow`)では、外部の鍵盤・ペダル・レバーは「♪ 演奏セット」タブと同じ(割り当て表、またはコードモード)に鳴らし、割り当てのまま音作りができる。画面の鍵盤は、いつもタブの ch だけ(試聴用)
- 場所が変わった瞬間に、鳴っている音を止める(ノートオフは鳴らしたときと同じ所へ)。切り替えたときも同じ
- ペダル・ベンド・モジュレーションは、「♪ 演奏セット」タブでは `controls`(5.3.5)どおり。「1」〜「5」のタブでは開いている ch へそのまま(モジュレーションはビブラート)
- **鍵盤から使うのは、ノート・ピッチベンド・モジュレーション・サスティンペダル(CC#64)・アフタータッチだけ**(1.5-7)。プログラムチェンジ・そのほかの CC は使わない(送らない。ログには「鍵盤の操作は使わない」と残す)

### 6.5 コードモード

#### 6.5.1 鍵盤(音を鳴らすだけ。37鍵 C3〜C6 に収める)
| 鍵 | 役割 |
|---|---|
| C3〜B5(36鍵) | コード(配置は 6.5.2) |
| C2〜B2(オクターブ DOWN) | 入りきらなかったコードだけ(ふだんは使わない) |
| C6 | なにもしない(今の版の「C6 を押したまま曲・キー・機能」はなくす) |
| サスティンペダル(CC#64) | 踏んでいる間は離してもコードを保持(`controls.pedal`) |

- **曲・キー・ホールド・止めるは、画面とパソコンのキー**で操作する(今の版のオクターブ UP の機能キーと C6 の組み合わせはなくす): 「♪ 演奏セット」タブの曲の一覧・キーの選択・「ホールド」「止める」。キー: ←/→ 曲、↑/↓ 移調、H ホールド、Esc 止める、スペース コードモード ON/OFF(文字入力中は除く)
- 押している鍵が複数あれば、最後に押した鍵のコード。離すと、まだ押している鍵に戻る(**戻るときは打ち直さない**)
- ベンド・モジュレーションは `controls` の `to` に入っているボイスへ

#### 6.5.2 鍵盤の配置(`layout`)
コードは**キーからの度数**で置く(どのキーでも同じ指)。実際に鳴るコードは曲のキー(+移調)に合わせる。

- (2026-11-06 ユーザー判断: **オタマ互換(`"otama"`)・規則性重視(`"regular"`)はなくした**。保存してあった設定は読むときに `"song"` になる。それにしか使わなかった「全曲共通のコード(4段目)」の編集もなくした)
- **`"song"` 曲の弾きやすさ重視**: 曲のコードを C3〜B5 の36鍵に置く。弾きにくさ = Σ(続けて弾く組の回数 × 鍵の横距離)+ Σ(使う回数 × (黒鍵なら 5 + 0.08 × 真ん中 F4 あたりからの横距離))。横距離は白鍵1つ = 1、黒鍵は白鍵の間。使う回数の多い順に「白鍵・真ん中に近い」鍵から置き、入れ替え・空いた鍵への移動で弾きにくさが減らなくなるまで直す(同じ曲なら毎回同じ結果)
- 表記: フラット系のキーと ♭Ⅱ・♭Ⅲ・♭Ⅵ・♭Ⅶ は ♭ で書く

- **`"degree_r"` / `"degree_l"` 度数+補足**(2026-11-05 ユーザー要望。インスタコードのような「基本コード+補足の同時押し」。押し方はインスタコードと同じではないが、インスタコードで弾けるコードの種類 = maj・m・7・m7・M7・mM7・6・m6・add9・madd9・sus4・dim7・aug・m7-5・分数コード をすべて弾ける。計算は `music/degree.py`)
  - 鍵盤を**3つのオクターブに分ける**(37鍵 C3〜C6 にそのまま収まる)。`degree_r`(右手で基本コード): C3〜B3 = 補足、C4〜B4 = 基本コード、C5〜B5 = 分数のベース。`degree_l`(左手で基本コード): C3〜B3 = 基本コード、C4〜B4 = 分数のベース、C5〜B5 = 補足(ユーザー指定。右手の上の2オクターブが補足側)。C3 より下は C3〜B3 と、C6 から上は C5〜B5 と同じ扱い(2026-11-05 ユーザー指摘: 余っている上のオクターブを分数用に)
  - 基本コードの側(12鍵): 白鍵 = いまのキーの Ⅰ・Ⅱm・Ⅲm・Ⅳ・Ⅴ・Ⅵm・Ⅶm、黒鍵 = ♭Ⅱ・♭Ⅲ・#Ⅳm・♭Ⅵ・♭Ⅶ。キーは − / + で移調できる(曲ごとに並べ直さない)
  - 補足の側(12鍵、いくつでも重ねられる): C = 7、C# = 6、D = M7(7 と一緒なら 6th)、D# = ♭5、E = ～(メジャー⇔マイナー)、F = sus4、F# = ♭(コード全体を半音下げる)、G = add9、G# = /3rd(ベースを 3rd に)、A = dim7、A# = /5th、B = aug。例: Ⅲm+～+7 = Ⅲ7、Ⅶm+7+♭5 = Ⅶm7♭5、Ⅴ+7+add9 = Ⅴ9
  - 補足・ベースの鍵だけを押しても鳴らない。基本コードの鍵を押すと鳴る(打ち直す)。押さえたまま補足・ベースを足す・離すと、その場で和音が変わる(打ち直さない)。基本コードの鍵を全部離すと止まる(つなぎの猶予・ペダル・ホールドは今までどおり)
  - **離すときの猶予**(2026-11-05 ユーザー指摘): 鍵を離しても 0.1秒(`degree.RELEASE_WINDOW`。実機で調整)は残った鍵のコードに切り替えない。その間にほかの鍵も離したら途中のコードは鳴らさない(同時に離したつもりでずれても、後に離した鍵の音が出ない)
  - アシスト: 次に弾くコードを、基本コードの鍵と補足の鍵に分けて光らせる(いちばん少ない鍵の押し方。♭・～はなるべく使わない)。コードの表は3段(分数のベース・基本コード・補足)。作れないコードは「鍵盤に入りきらないコード」に出す
  - 進行は「次のコード」ができた瞬間に1つ進む(補足を足して次のコードになったときも)。補足を離して元のコードに戻っても進まない
  - **分数コード**: **分数のベースの鍵**(右手で基本コードなら C5〜B5、左手なら C4〜B4)を押しながら基本コードを弾く。ベースの鍵の並びは基本コードと同じ度数(オクターブの C = Ⅰ の音。キー C で右手なら G5+Ⅳ = F/G、G5+Ⅵm+補足7 = Am7/G。左手なら G4+Ⅳ)。ベースは補足の ♭ では下がらない。/3rd・/5th の補足で作れるものは補足で、それ以外はベースの鍵で案内する。(最初は「基本コードの鍵2つの同時押しで低い方がベース」(案A)にしたが、ベースの鍵が1オクターブ下になるのが弾きにくいと言われて、この形に変えた)

#### 6.5.3 声とボイシング
- **ベース** = ch3。ベース音(分数コードなら指定の音)の、`bass_floor` 以上で一番低い音
- **上の声**:
  - ボイスへの割り振り順: 3度(無ければ sus の4度・2度)→ 7度 → 減5度・増5度 → 6度 → テンション(♭9, 9, #9, 11, 13)→ 完全5度 → ルート。dim・m7♭5 は ♭5 を 7度より先。分数コードは、ベースが鳴らす音を一番後ろ・ルートを3度の次へ
  - `"split"`: 上の順に3つ。音域内で、前の和音からの動き(各声の差の合計)+ 0.5×(平均の音と音域の真ん中の差)+ 3×(半音で隣り合う組)+ 0.4×(1オクターブを超えて広がる半音)+ 2×(3度・7度の重複)が一番小さい形。**順位の高い2音をボイス1(パルス1、高い方)・ボイス2(パルス2)、3番目をボイス3(波形メモリ、ch5)**。パルスは前と同じ音をそのまま受け持てる並びを優先
  - `"arp"`: 構成音を全部(最大5)近い形で `arp_ch` へ
- 3声に入りきらないときに落とす音: 5度・ルートから(上の順の後ろから)

#### 6.5.4 鳴らし方
(数値は 5.5 の奏法プリセットから)
- 押したとき: `retrigger` なら全部の声を「ノートオフ → ノートオン」で打ち直す(だんだん消える音色で、消えた声が戻らずベースだけになったため)。`retrigger` でなければ、同じ音の声はそのまま、変わる声は「新しい音のノートオン → 古い音のノートオフ」(つないで持ち替え)
- ずらし: 新しく入る声(`strum_change` ならコードチェンジで変わる声も)を `strum_order` の順に `strum_ms` へ均等に散らす(+`jitter_ms` の乱数)。同じ高さならベースが先に入り、抜けるときは最後
- 全部離したとき: つなぎの猶予(80ms)待って、その間に次を押さなければ止める(`release_ms` で抜けをずらす)。猶予中に次を押したらコードチェンジ
- ホールド中・サスティン中は離しても止めない
- 時間で動くものは1本のスケジューラ。後から別の指示が来たら、予約を番号で取り消す

#### 6.5.5 画面への知らせ
状態が変わったら(コード・曲・キー・ホールド・ON/OFF)画面へ: いまのコード名と段・位置、曲名、キー名。

#### 6.5.6 コードモードの間だけ変える設定
入るとき: `"split"` なら ch5 を波形メモリ(CC#18=127)、`"arp"` で arp_ch のアルペジエーターが OFF なら CC#23=127、`glide` なら ch1〜3 に CC#65=127・CC#5。ch5 の音色に波形があれば送る。
抜けるとき: Session の音色の値に戻す。どちらも**音色と同じ間引きの列**に入れる。間の音色の変更ではこれらを送らない。

### 6.6 カートリッジへの書き込み

#### 6.6.1 2段階
1. **計画**: 何をどこに書くか・確認文・送信手順(待ち時間付き)・成功/失敗したときの控えの更新、を作る(送らない)
2. **確認画面**: 「元に戻せない」にチェックしないと進めない。かかる秒数と「電源を切らないで」を出す
3. **実行**: 番号札で計画を実行。前後にパニック。書き込み中はほかの送信を止める。進み具合を画面へ。予定時間+20秒を過ぎたら「応答がない」と出し、閉じることを許す(中身は不明として控えに残す)

#### 6.6.2 送信手順と待ち時間
- 記録: `CC#49=47`(ユーザーマクロ)→ 600ms → `CC#45=m`(記録開始)→ 600ms → CC を75ms おき(10個まで)→ 600ms → `CC#45=0`(停止・保存)→ 1800ms → `CC#47=m`(実行)
- 割り当て: 実行のあと 900ms → `CC#51=PC-1` → 600ms → `CC#50=ch`(電源ON)→ 600ms
- 波形の登録: 波形データ → 150ms → 登録 SysEx → 600ms
- 記録に使う ch は ch1(ch は記録されない)

#### 6.6.3 画面の操作 → 計画
| 操作 | 書くもの |
|---|---|
| 保存場所 N に音色を入れる | 空いているマクロ(か、その場所の今のマクロ)に10個を記録 → PC(88+N) に割り当て |
| 保存場所を空にする | PC をマクロ19(音量最大)に割り当て |
| 電源を入れたときの音色 | 保存場所のマクロを ch の電源ONに / 「ふつう」= マクロ19 |
| 整える(ch ごと) | 6.6.4 |
| 波形の登録 | 波形データ+登録 SysEx |
| 詳細な管理 | 1つずつ試す・まとめて割り当て・10項目を選んで記録・記録済みマクロの割り当て・内部の対応表 |

#### 6.6.4 整える(同じ ch の音色どうしで切り替えても、前の音色の設定が残らないようにする)
- ch ごとに、その ch 用の音色が入った保存場所を集める
- **土台** = 全員で同じ値かつ既定値と違う設定(効いていない設定は比べない: アルペジエーター OFF なら速さ等、ポルタメント OFF、ビブラート・トレモロ量が無効区間以下、サスティン最大ならディケイ。ブレス・アフタータッチのタイプは無視)。重要度順に10個まで → 電源ONマクロに
- 各音色の10個 = 「既定値+土台」と違う設定+ほかの音色が違う値にする設定(後始末)。収まるまで数回くり返し、余りは自分の設定で埋める
- 入りきらない設定は「切り替えで残ることがある」と知らせる

## 7. 画面

### 7.1 全体
```
┌ 上の帯: ロゴ・接続の状態(押すと接続の小窓)・🎮仮想ファミコン・★カートリッジ・✓実機の確認・パニック …… ⚙(テーマ・ch のずれ)
```

- **🎮 仮想ファミコン**(2026-11-05 ユーザー要望): ふぁみみみっでぃが無くても試してもらうための、このパソコンで鳴らす音源。押すたびに 仮想ファミコン ⇔ 本物(前につないでいた出力)を切り替える。接続の小窓の出力の一覧にも「仮想ファミコン(このパソコンで鳴らす)」が出る
  - 作り: 出力ポートの偽物(`device/virtual.py`)。送信の関所・ログ・コードモードは本物と同じ道を通り、送ったメッセージを画面の音源(`web/vfc.js`、WebAudio)がまねて鳴らす。凝らない(なんとなく似ていればよい)。実装表の値どおりに、デューティ比・エンベロープ(アタック・レベル/時間、ディケイ、サスティン、リリース)・ボリューム・エクスプレッション・ベロシティ(16段階/三角波は ON/OFF/波形メモリ 32段階)・ビブラート(CC#1・不感帯・レート・デプス・ディレイ・波形)・トレモロ・ポルタメント・ピッチベンド(幅 CC#82)・デチューン・ノート記憶・アルペジエーター(2ノート以上、低い順)・サスティンペダル・ノイズ(ノートマップ・長/短周期・CC#17)・DPCM(ドラムはそれっぽい合成音。音量は効かない)・波形メモリ(SysEx の波形)。スイープ・ブレス・アフタータッチ・各マクロはまねしない

  - **カートリッジへの書き込みと実機の確認はできない**(控えは本物のカートリッジの唯一の記録なので、仮想で書き込むと狂う)
- **左の一覧とタブはひとつ**。「♪ 演奏セット」のタブは左の列と同じ幅で、その下の左の列に演奏セットの一覧が出る。「1」〜「5」のタブを開くと、左の列はその ch の音色の一覧に変わる(10章-7: 演奏セットが主役。音色はその ch のタブを開いたときだけ出る)
- **左の一覧の中身**:

| 開いているタブ | 左の一覧 | いちばん上のボタン | ほかのボタン |
|---|---|---|---|
| ♪ 演奏セット | 保存した演奏セット | (なし。**名前を押すとそのまま切り替わる**。2026-11-17 ユーザー要望) | 上書き保存・新しく保存・名前を変える・削除・…(バックアップ・取り込み) |
| 1・2 | パルス用の音色(ch1・ch2 共通)+おまかせの見本 | この ch に入れる | 上書き保存・新しく保存・名前を変える・削除・… |
| 3 / 4 / 5 | その種類の音色+おまかせの見本 | この ch に入れる | 同上 |

- いま入っている音色・読み込んでいる演奏セットに印。紐付け中の ch2 は ch1 の音色に印
- 演奏セットの名前・「変更あり」・「送り直す」はタブの上。**いま触っているものが何か**がいつも見える
- 下の鍵盤の左上に、いまの鍵盤の鳴り方(「演奏セットどおり ― コード」「音色づくり ― 1 パルス だけ鳴る」)を小さく出す(切り替えのボタンではない)

### 7.2 「♪ 演奏セット」タブ(演奏する場所)
- 弾き方: [🎹 割り当て表で弾く] [🎸 コードで弾く](= `chord.active`)
- **割り当て表で弾くとき**:
  - 鍵盤の絵(C2〜C7)の上に、ch ごとの色の帯(鍵域)。帯の端をつまんで動かす。帯の右の「↓1」などでオクターブ。使わない ch は下の空き行に置き、引き上げると使う
  - ch1 と ch2 が重なっているところ: ch1 のみ / ポリ(2音)/ ユニゾン(重ねる)
  - ひな形: 色の小さな絵付きのボタン(ch1 だけ・ベース+メロディ・ベース+ポリ・ベース+ユニゾン・ポリ)
  - 下の鍵盤の絵も鍵域の色に染める
- **コードで弾くとき**:
  - いまのコード・次のコード、キー(− / + で移調)、ホールド・止める
  - 曲の一覧(選ぶとその曲に)、「曲を編集・取り込み…」(曲名・キー・コード進行のテキスト、オタマのコードセット・ChordWiki の取り込み、コードセットの JSON の書き出し)
  - 鍵盤の配置: [弾きやすさ重視] [度数+補足(右手)] [度数+補足(左手)] と、コードの表(段 × 12鍵。いまのコードは緑、次は枠)。下の鍵盤の絵では次に弾く鍵が光る
  - 進行は**行ごとの譜面**(曲のテキストの行と小節線)。ChordWiki から取り込んだ曲は、ページ(`source`)を**表示するときだけ読んで**、見出し(Aメロ・サビなど)と歌詞をコードの下に出す。歌詞はどのファイルにも保存しない(歌詞は取り込まない決まりのまま)。曲のコードを編集してページと合わなくなったとき・ページが見つからないときは、歌詞を出さずに一言出す。移調するとコード名もずらす。欄の中だけ、コードが変わるたびに少しずつなめらかにスクロールし、いまの行をいつも欄の上から 3分の1 あたりに置く(大きく飛ばない。2026-11-05 ユーザー要望)。長い行は細かく折り返す(コードとその下の最初の数文字だけをひとかたまりにし、残りの歌詞は1文字・英単語ごとに折り返せる。2026-11-05 ユーザー要望)。
  - 進行(いまのコードは緑、次に弾くコードに枠)。**次に弾くコードを新しく弾いたときだけ1つ進む**。ほかのコードを弾いても、同じコードを弾き直しても、離して押さえたままのコードに戻っても進まない(飛ばさない。2026-11-05 ユーザー指摘)。進行のコードを押すと、そこを次に弾くコードにする
  - ボイシング: [4声] [アルペジエーター]、4つの枠 = ベース(3 三角波、音域 C2〜/C3〜)・ボイス1(1 パルス、グライド)・ボイス2(2 パルス)・ボイス3(5 波形)。下に割り振り順(3rd → 7th → ♭5/#5 → 6th → テンション → 5th → ルート)
  - 奏法プリセット: ピアノ / オルガン / ギター / パッド(発音のずれの絵付き)と、ストラム幅のつまみ
- **ペダル・レバー**(どちらの弾き方でも): サスティンペダル・ピッチベンド・モジュレーションの3行(5.3.5)
- この演奏セットの音色: 5つの ch の音色の名前(ch の色の枠。押すとその ch のタブへ。紐付け中の ch2 は「ch1 と同じ」)

## 8. 実機テストと開発の約束

- **Claude は音を聴けない**。ハードウェアに関わる機能は、ユーザーが耳で判定できる**二択**(鳴る/無音)の手順とセットで作る。調べたい CC を先頭に
- **実機の確認は、アプリの中の「確認モード」で行う**(8.2)。手順書を読みながら手で設定を変えたり、Domino でファイルを再生したり、結果を「A=y B=n」と打ったりしなくて済むようにする
- 送ったものはすべてログ。ユーザーの報告とログを突き合わせる。**報告とログが合わなければ、まず二重起動・ほかのソフト(Domino/Cubase)を疑う**
- 書き込み系の機能は、実機で確かめてもらうまで「完成」と言わない
- 見た目の確認にデスクトップのスクリーンショットを使わない(ほかのウィンドウが写る)。動作は偽のポートで画面を開いて JS から、見た目は Bridge の答えを埋め込んだ1ファイルの HTML をアプリ内のブラウザで
- 実際の `user_data` をテストで書き換えない(一時フォルダ・保存先の差し替え。前後で md5 を比べる)
- **画面のタグの対応をテストで確かめる**(閉じ忘れで画面が崩れた)
- `run.bat` は cp932・CRLF、2行目の `chcp 932` を消さない。書き込めないフォルダ(Program Files)では案内して止まる。使える仮想環境が無ければ `%LOCALAPPDATA%\FamimimidiEditor\venv` に作る
- 公開: 手元の main は公開しない(作者さんの実装表 PDF が履歴にある)。公開用の履歴を `tools/publish.py` で作る。作者さんとのやりとりは公開側に書かない

### 8.2 確認モード(実機の確認の自動化)
今の版では、確認のたびに手順書(`hw_tests/*.md`)を読み、ボリュームを手で0にし、Domino で MIDI ファイルを再生し、「A=y B=n …」と打って報告してもらっていた。手順の抜け・取り違えが起き、入力も手間だった。作り直しでは:

- 確認の手順を**データ**(手順の列)として持つ: 1手順 = 「アプリが送るもの(自動)」+「ユーザーへの問い(鳴った?)」+「期待する答え」
- アプリが**自分で送って鳴らし**、画面に大きく「いま鳴りましたか? [鳴った] [鳴らない] [もう一度]」を出す。答えは押すだけ。設定の変更(ボリューム0など)もアプリが自動で行い、終わったら元に戻す
- 結果は `user_data/checks/日時_名前.json` とログに自動で残る(ユーザーが結果を打ち写さなくてよい)。Claude はそれを読む
- 手順の途中でやめられる。やめても設定は元に戻す
- 確認の種類: 新しい機能の確認、書き込んだ保存場所を1つずつ試す、V0(音量0でも鳴るか)など
- ほかのソフト(Domino/Cubase)が動いていたら、始める前に知らせる
