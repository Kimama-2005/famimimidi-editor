## フェーズD: 演奏(複数の ch を同時に鳴らす)(2026-10-01 ユーザーと合意)

目的: **ベースとメロディを1人で同時に弾く**。ふぁみみみっでぃは各 ch が単音(Mode4 固定)なので、アプリのスルーで鍵盤の演奏を ch に振り分ける(microKEY2 は送信 ch を変えられない)。カートリッジへの書き込みはない。

| # | 機能 | 状態 |
|---|---|---|
| D1 | **2音**: 上の鍵域を ch1・ch2 に振り分ける(3音目は一番古い音を止める。1音ずつ弾くと ch1/ch2 を交互に使い、前の音の余韻を切らない)。2音の間は ch1 の音色を ch2 にも送る | **完了(2026-10-01、`hw_tests/PLAY_CHECK.md` A〜G 合格)** |
| D2 | **鍵盤を分ける**: 境目より下を別の ch(初期値 ch3 三角波)へ。オクターブずらし付き。D1 と組み合わせて最大3音 | **完了(同上)** |
| D3 | **重ねる**: 同じノートを ch1 と ch2 の両方へ(1音)。音色は ch1・ch2 を別々に作る(2音と違ってそろえない)。「ch1 の音色を ch2 にコピーして少しずらす」(ch2 のデチューン +8)| **完了(2026-10-01、`hw_tests/LAYER_CHECK.md` A〜D 合格)**。ただし「少しずらす」のうねりは D4 などで弱く聞こえる音があった(ユーザー報告)。ファミコンの音程は段階でしか作れないため、ずれの実際の量が音ごとに変わる(推測。計算では +8 セントは D5 で 0 段)→ ずらす量を少し(8)/普通(16、初期値)/強め(24)から選べるようにした(確認 `LAYER_CHECK.md` F〜H 合格、F36)。**フェーズD 完了(2026-10-01)** |

- 振り分けは `famimimidi/play.py`(`PlayRouter`、画面から独立)。engine のスルーが使う。ノートオンで決めた送り先を覚え、ノートオフは同じ ch・ノートへ送る
- ノート以外(CC・ピッチベンド・PC)は上の鍵域の ch へ送る
- 画面の鍵盤は今までどおり開いているタブの ch で鳴らす(振り分けは外部の鍵盤だけ)
- 設定は `user_data/settings.json` の `play`(以前の「開いているタブのchで鳴らす」のオン/オフは引き継ぐ)。予備の tkinter 版はこれまでどおり
- 候補: Domino 用に「和音の入った1トラックを ch1/ch2 に振り分けて書き出す」

## フェーズE: 演奏セット(2026-10-01 ユーザーと合意)

目的: ライブラリに「5チャンネル分の音色 + 鍵盤の割り当て」をまとめた**演奏セット**をしまえるようにする。鍵盤の割り当ては「上/下の2分割」から、**5つの ch それぞれに鍵域を決める汎用の割り当て表**にする。

ユーザーの決定:
1. **2階建て**: 今の「音色」(1ch 分)は部品として残し、その上に「演奏セット」を作る
2. セットの中の音色は**コピー**(元の音色を直してもセットは変わらない)
3. カートリッジとの互換性は **(1) セットの音色を保存場所に入れる/呼び出し番号で切り替える、(2) 電源を入れたときのセット** を先に。(3) 鍵盤からの呼び出し番号でセットごと切り替える は後で
4. 割り当ては 鍵域・オクターブ・2音/重ねる。強さでの振り分けは不要

カートリッジとチャンネルの関係(説明済み): 保存場所は ch を持たない音色の部品。呼び出し番号の対応表は全 ch 共通、電源ONは ch ごと。**鍵盤の割り当てはカートリッジに保存できない**(アプリ・鍵盤・シーケンサー側の役目)。

| # | 内容 | 状態 |
|---|---|---|
| E1 | 割り当て表(ch ごとに 使う/鍵域/オクターブ/ホイール類を受ける、ch1+ch2 は 別々/2音/重ねる)、演奏セットの保存・読み込み(ライブラリに「音色」「演奏セット」の切り替え) | 作成済み・実機確認待ち(`hw_tests/E1_CHECK.md`) |
| E2 | セットの音色をカートリッジの保存場所に入れる(まとめて1回の確認)。入っていれば、セットの読み込みを呼び出し番号(5つの PC)で行う | E1 の後 |
| E3 | 電源を入れたときのセット(5 ch の電源ONをまとめて)。「整える」の土台との両立を設計してから | E2 の後 |

設計(E1):
- アプリの今の状態(5 ch の音色 + 割り当て表)が「演奏」。セットはそのスナップショット。読み込むと 5 ch の音色を送り、割り当て表を入れて「割り当て表で鳴らす」にする
- 鍵盤の弾き方は「開いているタブのch(音色づくり)/割り当て表で鳴らす/鍵盤のchのまま」の3つ。以前の 2音・重ねる・鍵盤を分ける は割り当て表で表す(設定は自動で移す)。よく使う形は「ひな形」から選べる
- 1つのノートは、鍵域に入るすべての ch で鳴る(鍵域を重ねれば重ねる、ずらせば分ける)

## フェーズC 技術調査(2026-09-30)

### 候補1: pywebview(推奨)
Python から Windows 標準の WebView2(Edge の画面表示部品)でウィンドウを開き、中身を HTML/CSS/JS で作る。

- この PC で**実際に動作確認済み**(一時フォルダの使い捨て環境で試作)
  - 画面 → Python の呼び出し(ボタンから `winmm.list_outputs()` を呼んでポート一覧を表示)
  - Python → 画面への通知(送信ログを画面に流し込む)
  - SVG で減衰の形を描画、ゲーム画面風の枠・▶カーソル・影つきボタン
- 必要な部品(すべて Python 3.14 用の配布版あり): pywebview 6.2.1、pythonnet 3.2.0(cp314 対応)、clr_loader 0.3.1、cffi 2.1.1(cp314 の Windows 用)、bottle、proxy_tools、typing_extensions。**合計 約5MB**
- Windows 側: WebView2 ランタイム(この PC は 154.0)と .NET は Windows 11 に標準で入っている
- オフライン対策: 部品のインストール用ファイル一式(wheel)をプロジェクト内に保存しておけば、ネットなしで入れ直せる
- 注意: pythonnet(.NET 経由)に依存する。バージョンを固定して使う

### 候補2: 追加インストールなし(予備案)
Python 標準の HTTP サーバーをこの PC の中だけで立て、Edge の「アプリモード」(`msedge --app=...`)で開く。

- 長所: 追加の部品が一切いらない
- 短所: ウィンドウを閉じたことの検知、ポートの重複、画面⇔Python の通信を自前で作る必要がある。pywebview が使えなくなったときの逃げ道として残す

### 候補3: PySide6(不採用)
約200MB。見た目の自由度は高いが、ユーザーの希望(ブラウザ技術)と容量で候補1が勝る。

### 画面づくりの方針(案)
- 画面の中身(HTML/CSS/JS)はすべてプロジェクト内に置き、ネット上の部品(CDN)は使わない(オフライン)
- ドット風のフォントは、ライセンスが自由なものを同梱する(候補: DotGothic16、PixelMplus、美咲フォント。**ダウンロード前にユーザーに確認する**)
- 見た目はゲーム画面風、操作は現代的に: ドラッグ、ホイール、ツールチップ、元に戻す、キーボード操作
- 画面以外の中身(engine / spec / library / cartridge / sets / export)はそのまま使う
