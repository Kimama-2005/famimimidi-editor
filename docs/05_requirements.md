**段階4(2026-09-30〜)**:
- S6 Domino 音源定義ファイル → **作らない**(ユーザー判断: このソフトがあれば Domino は使わない)
- M7 MIDIファイル書き出し → 実装済み(ライブラリ「MIDIファイルに書き出し…」)。ch1〜5 に音色を選んで1ファイル。format 1・chごとにトラック・トラック名は Shift_JIS。書き方は「全項目(おすすめ)/音色の設定だけ/呼び出し番号だけ」
- S4 共通の土台 + 切り替えの後始末 → **A + B2 で合意・実装済み、実機確認済み(2026-09-30、docs/03 F29)**(`hw_tests/STAGE4_TIDY_CHECK.md`)。`famimimidi/sets.py`
  - 音色セット = カートリッジに入っている「同じ ch 用」の音色(ライブラリの channel で分ける)
  - 各場所の10項目 = 「既定値+土台」と違う設定 + ほかの音色が変える設定の戻し(A)。余った枠は自分の設定で埋める(場所を空にしない)
  - 土台 = 効いている音色どうしで値が同じ、かつ既定値と違う設定(最大10)。ch の「電源を入れたときの音色」として保存(B2)。「土台を今だけ送る」ボタンも付けた(B1)
  - 「効いていない設定」は気にしない: アルペジエーターOFF なら速さ等、ポルタメントOFF なら時間、ビブラート/トレモロが無効区間以下ならその設定、サスティン最大ならディケイ。ブレス(CC#3)とアフタータッチ種類(CC#30)は常に無視(KROSS2/microKEY2 が送らない前提)
  - 重要度順を変更: デューティ → アルペジエーター ON/OFF → アルペジエーターの速さ → サスティン…(アルペジオ系の音色の性格を守るため)
  - いまの ch1(J-POP 3種+ギター+Follin)では、どうしても入りきらない細かい設定が残る。表示はするが、よく切り替える組み合わせを別の ch に分ける運用で減らせる

**かんたん保存(2026-09-29、ユーザー要望「PCやマクロがよく分からない。簡易版がほしい」)**:
- メイン画面の「★ カートリッジに音色を保存(かんたん)」と、ライブラリの「★ カートリッジに保存…」から開く。ユーザー向けの標準の入口
- 言葉: 保存場所1〜40(= PC89〜128)、呼び出し番号(= PC番号)、電源を入れたときの音色(= CC#50)。マクロという言葉は出さない

- 10個の選別は自動(初期値と同じものを外し、docs/05 の重要度順 `IMPORTANCE` で先頭10個)。外れる設定の名前は確認画面に出す

段階3で追加したもの(実機の結果を受けて):
- 「PCを1つずつ試す」: 毎回 音量を127に戻す → PC → 1音 → ユーザーが鳴った/無音を押す(ログに残る)
- 「PCをまとめて割り当てる」: 複数の PC→マクロ をまとめて1回の確認で送る
- スルーの演奏を「開いているタブのch」で鳴らす(microKEY2 はchを変えられないため)
- 書き込み中の警告ウィンドウ(電源を切らない・ケーブルを抜かない・ソフトを閉じない。閉じられない。進み具合と残り時間を表示)。書き込み中はメインウィンドウも閉じられない(ユーザー要望)

段階3の設計上の決定(2026-09-29、ユーザーから一任):
- PC の切り替えは KROSS2 など MIDI 側で行う。ファミコンのコントローラーでの校正は行わない(ユーザー判断)
- 記録は常に音源ch1で行う(マクロはchを記録しない F20)。手順と待ち時間は実績のある T0 と同じ
- 書き込み・割り当ては必ず確認ダイアログ(送信内容の全表示+「取り消せない」への同意チェック)を通す
- 書き込み中は、ほかの送信(エディタ・スルー・試聴・パニック)を止める。前後に自動でパニックを送る
- 対応表は `user_data/cartridge.json`。初回は docs/03 の 2026-09-29 時点の状態で作る。失敗時は影響したかもしれない番号を「不明」にする
- マクロ19(音量最大)・20(無音)はテスト用に予約。空きPC = マクロ19 が割り当てられているPC
- マクロ候補は「既定値と同じ値のCCを外し、音色の並び順のまま先頭10個」。並べ替え・除外は書き込み画面で行う

段階2の設計上の決定:
- 音色は「既定値と違うCCだけ」を**順序つき**で保存する(順序は段階3で先頭10個を選ぶのに使う)
- 読み込みは「全項目を既定値にしてから音色の値で上書きし、全部送る」。CC#121 を使わずに前の音色の設定が残らない。1ch 約42CC ≈ 40ms
- `data/patches.json` は初回起動時に `user_data/library.json` へ取り込む。CC#121 などリセット・書き込み・マクロ系CCは取り込み時に除外する

1. **土台**: 出力/入力ポートの選択、MIDIスルー、送信ログ(画面+ファイル)、パラメーター編集とリアルタイム送信(間引きあり)、パニックボタン。**書き込み系(CC#45/50/51、SysEx)は送れないようにする。**スルーでも書き込み系CCは遮断する
2. **試聴とライブラリ**: 画面上の鍵盤・テストフレーズ、音色の保存/読込(`data/patches.json` を初期ライブラリにする)
3. **カートリッジ書き込み**: S1(確認ダイアログ必須)、S2 スロット表、S3 検証ガイド
4. **書き出しほか**: M7 MIDIファイル書き出し(format 1、ch別トラック)、S4 共通土台、S6 Domino 音源定義 など

## 目的

1. ふぁみみみっでぃの音色を、CC番号を覚えずに**画面上で編集し、その場で音を確かめられる**ようにする。
2. 作った音色を**ライブラリとして保存・管理**する。
3. 音色を**カートリッジに書き込み**(ユーザーマクロ+PC割り当て)、KROSS2 やファミコンのコントローラーから呼び出せるようにする。
4. Domino / Cubase で使う **MIDIファイルを書き出す**。

## カートリッジ書き込みのアルゴリズム(S1)

```
入力: 音色 P(CC→値の対応), マクロ番号 m(1〜40), PC番号 pc(89〜128)
1. 既定値(電源ON時の値)と比べて、P の中で既定値と違うCCを抽出する
2. 重要度順に並べる(下の表)。ユーザーが並べ替え・固定できるようにする
3. 11個以上あれば警告し、上位10個だけを使う。落ちたCCを表示し、「共通土台」に回す選択肢を出す
4. 送信:
     CC49 = 47
     CC45 = m                     記録開始
     (CC 最大10個、30〜60ms間隔)
     CC45 = 0                     記録停止+保存
     待つ(1.5秒程度)
     CC47 = m                     実行 → 「最後に実行したマクロ」になる
     CC51 = pc - 1                PCに割り当て(pc=93 なら 92)
     待つ(1.7秒程度)
5. ローカルのスロット表を更新
6. ユーザーに「電源を入れ直して、PC{pc} を送って確認」を案内
```

同じ音色群で比べるなら、既定値との差ではなく**音色群の間で値が違うCC**を優先すると、少ない枠で差を出せる(J-POPリード3種で実際にそうした)。

## 技術選択肢(ユーザーと決める)

| 案 | 長所 | 短所 |
|---|---|---|
| **A. Webアプリ(Web MIDI API)** | インストール不要、Chrome/Edgeで開くだけ。UIを作りやすい | ブラウザ依存(Firefoxは要確認)。SysExは許可ダイアログが出る。ローカルファイル保存はダウンロード/読込になる |
| B. Python + GUI(mido / python-rtmidi + PySide6 等) | MIDIファイル処理が楽(既存スクリプトを流用可)。ファイル保存が自然 | 配布・インストールがやや手間 |
| C. デスクトップアプリ(Electron / Tauri + Web MIDI) | Aの操作性+ファイル保存 | 構成が重い |

事前調査時点の推奨は **A**(Windows + Chrome/Edge で、ユーザーが何もインストールせずに使える)。ただしユーザーの希望を優先する。

## 非機能要件

- 書き込み系の操作(CC#45, #50, #51, SysEx登録)は確認ダイアログを出す。取り消しできないため。
- 発音中は CC#121 を自動で送らない。
- 送信を間引く(MIDI帯域 約3,125バイト/秒)。
- 送信ログを常に残す。
- 日本語UI。パラメーター名は実装表の日本語名を使う(`name_ja`)。
